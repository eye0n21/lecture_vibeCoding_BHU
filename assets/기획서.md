# 기획서.md — 우리 팀 페이지 기획서

우리 팀 페이지의 내용이 이 파일 하나에 모입니다. 색·글꼴 같은 디자인 규칙은 DESIGN.md에 따로 둡니다(이름이 비슷하지만 다른 파일입니다).
- 미리 채워 와도 되고, 비워 둬도 됩니다. 빈 칸은 Claude Code가 인터뷰로 묻고, 묶음이 끝날 때마다 이 파일에 적어 줍니다.
- 2일차에 각자 쓴 기능 초안은 3절 표에 모아 적으세요. 5개 이내, 오늘 시연할 기능에 ★ 하나.
- 준비가 되면 채팅창에 "claude.md 파일을 읽고 html 페이지 작성 시작해"라고 하면 됩니다.

상태: 작성 전

## 0. 최종 문제정의문 (1일차 문제정의서 8번, 그대로)
- 문제정의문 →
- 결과물 유형 (가 소개 페이지 / 나 실제 웹서비스 / 다 소개+시연, 기본) →

## 1. 팀과 아이템
- 팀명 →
- 아이템 이름 →
- 한 줄 소개 (누가, 무엇을, 어떻게) →

## 2. 대상과 문제
- 주 사용자 (가명, 나이, 생활 상황 — 1일차 캔버스 ②) →
- 함께 쓰는 사람 (보호자, 가게 주인, 기관 등) →
- 가장 큰 불편 1 (캔버스 ⑥) →
- 가장 큰 불편 2 →
- 지금은 어떻게 버티고, 왜 부족한가 (캔버스 ⑦) →
- 그 사람의 실제 말 한 문장 (캔버스 ④ — 첫 화면 문장이 됩니다) →

## 3. 해결안과 기능
기능은 "누가 · 무엇을 누르거나 적으면 · 화면에 무엇이 보이나"로 적어야 Claude Code가 만듭니다. "관리한다", "연결한다"는 기능이 아닙니다. 로그인·결제·지도·문자 발송은 구분 칸에 "흉내"라고 적습니다.

| 번호 | 기능 이름 | 누가 쓰나 | 무엇을 누르거나 적나 | 그러면 화면에 무엇이 보이나 | 필수 / 있으면 좋음 / 흉내 |
|---|---|---|---|---|---|
| 1 |  |  |  |  |  |
| 2 |  |  |  |  |  |
| 3 |  |  |  |  |  |
| 4 |  |  |  |  |  |
| 5 |  |  |  |  |  |

예시 한 줄(샘플 「오늘약」, 우리 팀 내용 아님): ★ 오늘 복약 체크 | 어르신 | 아침·점심·저녁 버튼 중 하나를 누름 | 그 칸에 도장이 찍히고 "오늘 2번 드셨어요" | 필수

- 오늘 실제로 눌러 보여줄 기능 (★, 위 번호 중 하나) →
- 운영 주체 (누가 운영하나) →
- 기대효과 한 줄 →

## 4. 페이지 구성
- 단일 페이지 / 멀티 페이지 중 →
- 들어갈 섹션 또는 페이지 (예: 소개, 문제, 기능, 시연, 팀) →

## 5. 시연 장면
- 사용자가 무엇을 누르거나 입력하면 →
- 화면에 무엇이 나타나는지 →
- 그다음 무엇을 누르면 →
- 화면에 보일 가짜 데이터 (가상의 이름·장소·수치 3~5개) →

## 6. 디자인 방향 (색·글꼴은 DESIGN.md에)
- 방식 ((A) getdesign 내려받기 / (B) 참고 캡처 / (C) 대화) →
- 이 아이템을 떠올리면 생각나는 물건·장소·색 (예: 약봉투, 골목 계단, 시장 천막, 가로등) →
- 다른 팀과 달라 보이는 한 가지 (첫 화면의 중심) →
- 분위기 (따뜻한 / 또렷한 / 공공기관 느낌 / 동네 가게 느낌 등) →
- 참고하고 싶은 서비스나 사이트 →
- 꼭 피하고 싶은 것 →
