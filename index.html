결과물 유형

셋 중 하나 — 기본은 (다)

Claude Code가 문제정의문을 확인한 직후 묻습니다. 해결안이 웹사이트면 (나), 시간이 빠듯하면 (가).

(가) 소개 페이지

구현 예정인 앱·서비스의 상세 내용을 한눈에 보는 페이지. 화면은 휴대폰 틀 안에 모형 2~4장을 넣고 “다음 화면” 버튼으로 넘겨 봅니다.

흐름

문제 → 하루 장면 → 해결안과 기능 → 화면 모형 → 운영 주체·다음 단계 → 팀

눌리는 것: 화면 넘기기·탭 전환

(나) 실제 웹서비스

해결안이 웹사이트인 팀. 그 서비스의 웹페이지 자체를 만듭니다. 문제·해결 과정 설명은 발표 자료가 맡습니다.

뼈대 (샘플 없음 — 이 순서대로)

  • 첫 화면: 서비스가 무엇인지 한 문장 + 바로 시작 버튼 + 대상자의 말 한 줄
  • 화면 1: 사용자가 처음 하는 일 (고르기·적기)
  • 화면 2: 그 결과 (목록·안내·확인)
  • 화면 3(선택): 저장·공유·다음 행동 — 흉내
  • 풋터: 팀·대회·“가상 데이터입니다”

눌리는 것: 핵심 기능 1개 (화면 1 → 화면 2)

(다) 소개 + 시연 기본

(가)의 소개 흐름에 시연 섹션을 더한 것. 시연 섹션의 휴대폰 틀 안에서 핵심 기능 1개가 실제로 작동합니다. 샘플 「오늘약」이 이 유형.

흐름

소개 → 문제 → 하루 → 기능 → 시연(눌림) → 팀

앱이 아닌 서비스(공간·프로그램·제도)면 신청서·예약·안내판처럼 “사용자가 만지는 화면” 하나를 시연으로

샘플 단일 페이지 · 샘플 멀티 페이지

막혔을 때

자주 막히는 문제 — 먼저 여기

설치·로그인

확장이 안 보여요

검색창에 ‘Claude Code’를 정확히. 그래도 없으면 VS Code를 최신으로 업데이트하고 재시작.

로그인 창이 안 떠요

브라우저가 뒤에 열려 있는지 확인. 팝업 차단 해제. 다른 브라우저로 시도.

로그인이 풀렸어요 / 응답이 없어요

Claude 아이콘 → 다시 로그인. 인터넷 연결 확인. 그래도 안 되면 팀의 다른 노트북으로 폴더를 zip으로 옮겨서 계속.

파일이 안 생겨요

폴더를 열지 않고 파일만 연 경우가 대부분. ‘파일 → 폴더 열기’로 폴더 자체를 열기. 탐색기에서 폴더를 새로고침(F5).

결과물

더블클릭했는데 빈 화면이에요

Claude Code에 “index.html을 더블클릭하면 빈 화면이야. 원인이 될 만한 것 세 가지를 들고 가장 유력한 것부터 고쳐줘”. 두 번 고쳐도 안 되면 “방금 전 상태로 되돌려줘”.

글꼴·이미지가 깨져요

이미지는 images 폴더에 넣고 상대 경로인지 확인. 글꼴은 인터넷이 없으면 기본 글꼴로 보이는 게 정상 — 읽히면 통과.

버튼을 눌러도 아무 일이 없어요

“‘○○’ 버튼을 눌렀는데 아무 일도 없어. script.js가 index.html에 연결돼 있는지부터 확인하고 고쳐줘”. 브라우저에서 F12 → Console에 빨간 글씨가 있으면 그대로 복사해 붙이기.

Claude Code 대화

엉뚱한 걸 만들어요 / 시키지 않은 것까지 바꿔요

“방금 변경 취소해줘” → 다시 시킬 때 범위를 말하기: “소개 섹션만. 다른 파일은 건드리지 마”. 한 번에 한 가지만.

같은 걸 세 번 시켰는데 계속 안 돼요

네 번째도 안 됩니다. 말을 바꾸거나(증상·캡처·오류 문구), 되돌리거나, 손을 드세요.

아까 정한 걸 다시 물어봐요 / 느려졌어요

대화가 길어져 앞을 잊는 중. “지금까지 결정한 것과 현재 상태를 기획서.md에 정리해서 저장해줘” → 새 대화 시작 → “CLAUDE.md와 기획서.md를 읽고 이어서 진행해”.

“완료했습니다”라는데 안 바뀌었어요

브라우저 새로고침(F5) 먼저. 그래도 그대로면 “index.html을 열어 보니 바뀐 게 없어. 어느 파일을 고쳤는지 보여줘”.

수치·기관 이름을 AI가 지어냈어요

그대로 쓰지 마세요. 출처가 있으면 출처와 함께, 없으면 숫자를 빼고 “한 사람의 사례”로. 기관은 가상 이름으로.
